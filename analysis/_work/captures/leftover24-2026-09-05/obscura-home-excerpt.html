Chrome is the bottleneck.

It was built for people browsing one page at a time, not software running thousands of sessions at once. That mismatch shows up as cost, latency, and flaky results.

01

Heavy at scale

Every Chrome instance eats memory and CPU. Run thousands of them and your bill climbs fast, all for features no agent ever touches.

02

Slow to start

Cold starts take whole seconds. Multiply that across every task in a pipeline and your throughput grinds to a crawl.

03

State bleeds between tasks

Cookies, logins, and cached data carry over from one run to the next. That leaks data and makes results impossible to reproduce.

A browser, redefined.

Obscura keeps only what machines need. Faster, cheaper, and safer than Chrome, with none of the rewrites.

<50ms

Boot on demand

Sessions boot in under 50 milliseconds, not seconds. Spin up when you need them, tear down when you're done.

Zero state

Clean every time

Every session is a fresh sandbox with nothing shared. No leaked cookies, no contamination, fully reproducible runs.

10× leaner

More per machine

A fraction of Chrome's memory footprint, so you pack far more concurrent sessions onto every machine you run.

CDP

Keep your stack

Works with Playwright and the Chrome DevTools Protocol. Point your existing scripts at Obscura and go.

From zero to a browser in one call.

Keep the Playwright or Puppeteer code you already have. Point it at Obscura over CDP and connect, drive, and scale, no rewrites.

01

Connect

One API key spins up an isolated browser in milliseconds. No servers to run.

02

Drive

Navigate, click, type, and extract data with Playwright or CDP. No rewrites.

03

Scale

Run thousands of sessions in parallel, with capacity sized to the job and operated for you.
